# Botanical editorial implementation record

## Scope and intent

Onour explicitly requested a full visual redesign using his stored design references. The prior functionality was not the requested outcome by itself. This iteration therefore changes typography, material palette, marketing composition and interior-page presentation while retaining the commerce and source-data boundary.

## Execution sequence

1. Retrieve the user's exact reference repositories and distinguish original user rules from prior assistant proposals.
2. Read the released main source at 497e67a and preserve original media and commerce hashes.
3. Record a separate DESIGN.md and a project-specific reference evaluation.
4. Write and execute failing design regressions, then implement the visual system and archive-photo selector.
5. Run local tests, type checks and lint. Build a static preview.
6. Render actual pages in the GitHub runner. Inspect the resulting desktop, Greek mobile, product and contact screenshots.
7. Refine sentence wrapping, compact badges and fixed mobile controls. Keep every image provenance label.
8. Run all existing customer and media suites plus the new design browser suite.
9. Only after the review gates pass, integrate and prove the live build and real page rendering.

## Deliberate choices

Warm paper and dark olive ink respond to the actual botanical material and avoid the previous dark shop masthead. Literata provides a distinct editorial voice. Figtree remains for controls and body copy. The first screen uses a single owner-supplied specimen, not a fabricated shop or portrait. The visitor chooses between three real photographs. Product grids retain conventional alignment because comparing products is a task, while story, shelves and category windows use differentiated compositions.

No 3D scene, analytics, generated statistic, invented testimonial or extra application dependency was introduced. The reference repositories inform design judgment, not product facts. Suggestions in third-party design prompts to randomize dates or invent believable business data are not followed.

## Verification boundaries

The initial five design tests produced four expected failures and one pass, then all five passed after implementation. The first browser review observed 51 layouts across all 20 locales, exercised the deliberate photograph selector and computed six text contrast pairs. Its logs and screenshots remain preserved. The final reports are authoritative for any later changes.

The first visual review prompted a smaller desktop headline that respects the sentence boundary, a badge that does not enlarge the compact header, and a fixed purchase bar explicitly contained within the viewport. The final design should be judged from the rendered result, not a test count.

This is self-review with automated browser evidence, not an independent human design critique or accessibility certification. Existing generated photographs remain illustrative. Native editorial review of all catalogue translations and real commercial launch prerequisites remain separate.
